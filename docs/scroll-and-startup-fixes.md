# إصلاح السحب وشاشة البداية

## التغييرات

- الرئيسية: إزالة طبقات 3D وحركات ظهور البطاقات، وإبقاء بطاقة التنقل ثابتة أثناء اللمس. أصبحت النصوص تحدد ارتفاع البطاقة، وزر الصدقة ينتقل إلى سطر مستقل عند ضيق المساحة.
- المكتبة: بطاقات عادية بعناوين تلتف وارتفاع مرن، مع تخفيف المرشحات والظلال وخلفية ثابتة للعنوان.
- التحميل: إزالة استيراد عشرات الأقسام تلقائياً من App وLayout والمكتبة؛ يبقى التحميل عند التنقل أو التركيز على الوجهة. سلوك المكتبة الصوتية الداخلي محفوظ.
- البداية: خلفية خضراء منذ تحليل HTML، وغطاء أصلي فوق WebView. ينتظر الغطاء التزام الصفحة المحلية، وفك صورة الشعار، وVisualStateCallback والرسم التالي قبل الاختفاء. غطاء HTML ينتظر محتوى React الفعلي. لا توجد إعادة تحميل تلقائية بعد أربع ثوانٍ أو عملية مسح لبيانات المستخدم؛ إعادة المحاولة صريحة.
- الأيقونة: تكبير الشعار في الأيقونة التقليدية المربعة من 80% إلى 84%، والدائرية من 74% إلى 76%، وإعادة توليد موارد الكثافات الست. بقيت طبقة Adaptive بحجمها الحالي لتجنب قص أطراف الخط العربي؛ تكبيرها بصورة ملحوظة يحتاج تغيير تركيب الشعار. أُصلح أيضاً خطأ نحوي كان يعطل سكربت توليد الموارد، وأضيف الخيار `--icons-only`.

## التحقق المنفذ

- فحص TypeScript ناجح، وبناء الويب ونسختَي Android Debug وRelease ناجحان.
- `node scripts/test-startup.mjs`: ستة اختبارات ناجحة لمسار التحميل البطيء والفشل وإعادة المحاولة والإظهار الطبيعي والحركة المخفضة والجاهزية المتأخرة.
- المتصفح: الرئيسية والمكتبة بعروض 320 و360 و412 بكسل، وخط 100% و130%، مع تمرير متكرر صعوداً وهبوطاً. لم تظهر بطاقات مخفية أو تجاوز أفقي؛ عولج انضغاط عنوان الصدقة الذي كشفه الاختبار.
- Android 9 / API 28، WebView Chrome 124: تثبيت نظيف للنسخة الاختبارية المنفصلة `com.azkaralmumin.app.debug`، ثم تسجيل أول فتح. رُصدت 3 إطارات سوداء قبل إصلاح الغطاء الأصلي؛ بعده لم يظهر إطار أسود أو أبيض فارغ ضمن 200 إطار مسجل. هذا فحص للتسجيل المتاح وليس قياساً مضموناً لكل إطار على كل جهاز.
- السحب الفعلي عبر Android، مع قياس DOM: بقيت بطاقات التنقل الـ14 في الرئيسية والـ16 في المكتبة موجودة، وكانت العناوين ظاهرة دون أبعاد صفرية. بقي شريط التنقل أسفل النافذة وموضع تمرير المستند صفراً بعد دورات الصعود والهبوط.
- نجح التحقق من توقيع ملف Release بواسطة `apksigner`، بتوقيع APK v2.

اختبار Android 16 / API 36 لم يُعتمد: تعطل System UI وGoogle Play Services في المحاكي قبل اكتمال تشغيل التطبيق. يحتاج هذا الإصدار إلى تحقق بصري على هاتف حديث؛ لم يُعتبر هذا الاختبار نجاحاً.

## ملفات التسليم وإعادة البناء

ملف التثبيت: `android/app/build/outputs/apk/release/app-release.apk`.

يلزم Node.js 22 أو أحدث وJDK 21. من جذر المشروع:

```powershell
npm run lint
node scripts/test-startup.mjs
npm run build:web
node scripts/sync-android.mjs
java -jar android/gradle/wrapper/gradle-wrapper.jar -p android assembleRelease
```

استُخدم استدعاء Java المباشر لأن `gradlew.bat` في هذه البيئة يسيء تمرير مسار المشروع العربي ويختار JAVA_HOME القديم. نسخة Release لا تتيح فحص WebView؛ التفعيل مقصور على النسخة القابلة للتصحيح.

مراجع السلوك الأصلي: [ضمان الإطار التالي في WebView](https://developer.android.com/reference/android/webkit/WebView#postVisualStateCallback(long,%20android.webkit.WebView.VisualStateCallback))، و[تصميم أيقونات Android التكيفية](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive).
